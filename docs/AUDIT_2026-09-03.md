## 1. Executive verdict

PB&J has a coherent private-demo core. The canonical path keeps creative judgment in three bounded OpenAI roles, deterministic validation and ownership checks in application code, and media execution in FFmpeg. The audit found no reason to weaken CRF 20/medium output, render QA, evidence validation, repair limits, source ownership, explicit approval, or learning boundaries.

The highest-value improvements were removal of duplicated work and correction of state races:

- Canonical uploads now stream once to disk while hashing, rather than relying on a fully parsed multipart body.
- Upload sessions now carry an immutable browser-draft ID in addition to exact name, prompt, and selected-style checks. The visible New Project action rotates that identity through a same-origin-protected POST, while a GET can only resume the current draft; even an identical new brief cannot inherit old footage, and a cross-site navigation cannot clear one. Unreadable staged copies are removed while readable files remain retryable.
- Promotion of a 256 MiB staged file changed from copy-plus-rehash to same-filesystem hard-link promotion with a safe copy fallback: approximately `0.186 s` to `0.002 s` in the controlled local experiment, while eliminating a second physical copy on the normal path.
- Fourteen independent inspections changed from approximately `0.422 s` sequentially to `0.215 s` with a process-wide two-worker limit in the synthetic inspection fixture.
- Equivalent concurrent analyzer work now shares one permission-scoped cache result instead of paying twice.
- JSON read/modify/write updates and job admissions are serialized in the documented one-process topology.
- Cache reads now verify the embedded source checksum, and export failures that occur before FFmpeg starts no longer leave the project stuck in an active state.
- The main logo transferred by the UI is now 47,274 bytes instead of 1,442,098 bytes, a 96.72% reduction; the pinned source remains intact.
- Twelve Labs is now the sole analyzer in the worktree; the Gemini provider, dependency, configuration, UI, and current-workflow tests were removed together. Historical Gemini records fail safely, can still be removed locally, and record that remote cleanup is unavailable instead of restoring the retired provider.
- The service worker, offline page, cache-serving routes, and offline behavior were removed. Connected pages retain only migration cleanup that unregisters the retired worker and deletes its legacy `pbj-shell-*` cache from older installations.
- Hosted startup now fails closed on unsafe session configuration, including application-mode drift on Render and access/owner codes outside the supported 256-byte UTF-8 bound. Exact code comparison, bounded login throttling, same-origin mutation checks, logout, and security headers—including unhandled 500 responses—are implemented and covered by focused tests.
- Login/owner request bodies are rejected above 1 KiB before form parsing, and cookie-held project drafts now have character and Unicode-safe serialized-session limits that keep accepted cookies below 4 KiB.
- Approval, revision, export, and deletion paths now share atomic admission. A cut must match the exact current timeline and pass its render receipt before approval; stale cuts and overlapping jobs cannot overwrite active state. Failed newer edits show their failure instead of silently presenting an older cut for approval, and retry reuses the user's exact pending revision request. The unused direct timeline/editor API branch was removed after the owner confirmed there are no outside clients.
- Project and recipe deletion now take durable deletion claims, block new work/linkage while remote cleanup is pending, roll back to the exact prior state on cleanup failure, and recover safely after restart. Retired-provider references are retained in a private cleanup ledger without exposing identifiers in the UI.
- FFmpeg now has a duration-aware safety deadline, bounded output retention, isolated process-group execution, TERM-to-KILL cleanup, active-process tracking, and a shutdown admission gate in the worktree.
- A repository check workflow, `checksPass` deploy gating, a 300-second Render shutdown window, and a 240-second Uvicorn graceful-shutdown limit are defined in the worktree.

PBJ is **not production-ready for durable or public use**. The largest unresolved operational risk is process fate-sharing: uploads, provider work, JSON state, and FFmpeg remain in one disposable Render web process. Five pre-fix 14-source render attempts had a render-start event but no completion/failure event and coincided with abrupt restarts and 502s. This is strong evidence of container termination, with a short memory spike the leading hypothesis, but there was no explicit OOM/exit-137 record. Hosted low-memory FFmpeg controls are deployed at `1908657`. The owner-authorized controlled acceptance then completed a playable 60-second cut from 15 supplied videos without a restart or 5xx. It also demonstrated that this tier is close to its safe ceiling: CPU reached its full 1-core limit and sampled memory peaked at 1,930,330,100 of 2,147,483,600 bytes (89.888%).

The owner has explicitly accepted disposable private-demo storage for now and approved the security, FFmpeg-process, and deploy-drain work. The combined worktree passes the complete local suite, but an explicit commit/push/deploy decision is still required before those code changes can affect the live service. Durable storage and durable jobs remain mandatory before using real retained media. Render memory headroom and provider receipt reconciliation remain unresolved.

## 3. Critical-path architecture

```text
iPhone/desktop browser
  -> seven-day signed access session
  -> natural-language brief + optional finished references + raw footage
  -> streaming upload, SHA-256, ffprobe inspection (global limit: 2)
  -> Twelve Labs Pegasus analysis (sole supported analyzer)
       -> checksum/purpose/provider/model/prompt/permission cache
  -> Editing Agent: strict-schema candidate selection + edit proposal
  -> application-owned deterministic source/range/continuity repair
  -> Timeline Repair Agent: exact validation failure, at most 2 attempts
  -> application-owned timeline validation and immutable snapshots
  -> FFmpeg from original project media (global render limit: 1)
  -> ffprobe structural QA + hashes + render receipt
  -> playable rendered review
       -> prompt-driven revision, or
       -> explicit approval
  -> Learning Agent advisory assessment and scoped evidence
       -> only an explicitly approved successful render is positive evidence
```

The OpenAI layer does not execute commands, mutate storage, approve outputs, or promote shared recipes. FFmpeg does not make creative decisions. The retired proxy pipeline is removed, and the automatic path renders from original project assets.

## 9. Security, privacy, and AI-input safety

### Passed or materially improved

- In the uncommitted worktree, hosted startup fails closed unless the access code, a non-default session secret of at least 32 UTF-8 bytes, and HTTPS-only cookies are configured. Render's read-only platform marker forces that validation even if `PBJ_HOSTED_MODE` is missing, false, or malformed.
- Access and owner codes use exact, case-sensitive, constant-time comparison and share a 256-byte UTF-8 configuration/input bound. Failed access and owner attempts are limited per privacy-safe HMAC client fingerprint and globally in bounded process-local storage; submitted codes and raw client addresses are not retained by the limiter.
- Access and owner form bodies are incrementally capped at 1 KiB before form parsing, including requests without `Content-Length`. Cookie-held drafts limit names to 120 characters, descriptions to 1,600 characters, and the full prospective session JSON to 2 KiB, keeping accepted signed cookies below the common 4 KiB browser boundary even with Unicode escaping.
- Hosted unsafe browser methods require same-origin `Origin` or `Referer` metadata and reject explicit cross-site fetches. Beginning a distinct project is now a protected POST; GET—even with the retired `fresh=1` query—cannot clear the current draft. Logout clears access, owner, draft, and upload pointers while preserving only the local-mode device identity needed to recover that device's projects.
- Responses, including privacy-safe unhandled 500s, receive CSP, framing, content-type, referrer, permissions, transport (hosted), and cache headers. The current CSP still permits inline script/style because active templates depend on them; eliminating that allowance is a separate template refactor, not silently claimed here.
- Project/device checks are applied in middleware to project routes; private recipes enforce device ownership. Hosted shared-workspace behavior matches the documented single private-demo permission boundary and is not mislabeled as multi-user isolation.
- Session cookie is seven days, `SameSite=Lax`, HTTP-only by Starlette, and `Secure` when the Blueprint's HTTPS-only setting is active.
- IDs and persisted paths are constrained; project source normalization only accepts a unique project-owned alias.
- Tracked secret pattern scan found no credential values. Hosted settings cannot be changed through the app.
- OpenAI receives explicit role boundaries treating prompts, transcripts, filenames, analyses, recipes, and metadata as untrusted data.
- OpenAI uses strict JSON Schema output. Pegasus also requests schema output and caps at 12,000 tokens.
- Analyzer timings/confidence, source ranges, timeline continuity, linked audio, transforms, transitions, and export state are application-validated.
- Unknown/ambiguous source names and evidence are not guessed. Recipe citation repair and timeline repair are each bounded to at most two agent attempts.
- Models cannot provide executable shell/FFmpeg commands; FFmpeg arguments are compiled from validated typed data.
- Cache reuse now requires checksum, purpose, provider, model, prompt version, and permission boundary. Exact legacy records can be backfilled only inside their owning directory.
- Failure records, diagnostics, remote-deletion errors, media-inspection failures, timeline failures, render failures, and learning-assessment failures no longer persist raw exception strings in the audited paths.
- Direct timeline transaction routes are absent, so external callers cannot inject manual edits or forge their provenance.
- Approval remains separate from rendering and idempotent; failed/unapproved/stale renders cannot become positive learning evidence, and recipe approval cannot race active analysis or revision.

- The security hardening above is uncommitted and not live at revision `1908657`. Complete-suite verification and live session-secret rotation are complete; an explicitly approved code deployment and post-deploy access/logout/origin/header smoke tests remain.
- The login limiter is intentionally process-local and session cookies remain stateless. Distributed limiting, account identity, server-side session revocation, and multi-user authorization remain broader-beta work.

- Remote asset creation crash-window reconciliation remains incomplete. Deletion itself now has durable claims, exact-state rollback/recovery, and a private retired-provider cleanup ledger.
- The point-in-time dependency resolution scanned clean, but no lock/update process or CI advisory gate prevents later drift.
